# 项目复盘：从本地手账到私密共享服务

## 需求与场景

两位身处不同城市的用户，在同一间小屋保存文字、照片和留言；其他注册用户拥有各自独立的小屋。目标兼顾手机操作、视觉体验、授权边界和低成本部署。

开发由 AI 辅助。作者提出产品目标、使用场景与部署约束，参与实际试用、反馈及账号授权操作；代码实现、调试与文档整理使用 Codex 辅助。本文描述可核查的实现，不将生成代码量等同于个人独立编码能力。建议结合源码、测试及本人讲解评价项目。

## 1. 如何隔离不同小屋的数据

每条共享内容关联 `space_id`，成员表记录有效成员。客户端查询条件用于组织数据，真正的访问控制位于 PostgreSQL RLS 及 RPC。匿名账号不能读取私人表，登录但非成员也不能读取别人的小屋。

创建小屋和邀请接受通过数据库函数完成；事务锁串行化同账号建屋及同小屋成员变更，数据库检查两人上限。邀请绑定邮箱，核验邮箱验证状态、有效期、撤销状态和已加入状态。

核查：[CloudBase 迁移](../cloudbase/migrations/202611060001_private_space.sql)、[邮箱验证前置条件](../cloudbase/migrations/202611060003_username_profile.sql)、[权限测试](../cloudbase/tests/rls.test.mjs)。

## 2. 如何保护照片并处理部分失败

图片在设备端压缩为 JPEG，上传到私有桶。数据库元数据及存储路径权限共同检查成员和作者身份；页面使用 120 秒签名链接。

存储上传与数据库插入无法跨服务完成单个事务。上传批次复用稳定 UUID；响应丢失后重试会检查已有记录，避免再次上传已经完成的照片。部分成功时保留已成功项并显示可重试提示。

取舍：撤权不能收回已下载文件，已签发链接在剩余有效期内仍可能可用。当前不支持 HEIC 转换与离线后台上传。

核查：[上传重试实现及测试](../src/lib/cloud/reliability.ts)、[测试](../src/lib/cloud/reliability.test.ts)、[签名链接适配](../src/lib/cloud/photo-url.ts)。

## 3. 国内服务迁移遇到了什么

最初使用 Supabase，后续增加 CloudBase 上海适配。保留统一业务接口，分别封装认证、数据库及私有存储。

- 身份标识采用字符串，避免大整数 UID 转为 JavaScript Number 后丢失精度。
- CloudBase 传输层返回已解码 JSON，RPC 返回 UUID 时重新编码为合法 JSON Response，避免保存已成功但客户端解析报错。
- 两个平台签名照片链接字段不同，在边界层统一解析并验证 HTTPS。
- 国内版使用 10 秒轮询及窗口聚焦/联网刷新，页面明确标为定时同步；未将其描述成 WebSocket 实时推送。

核查：[会话测试](../src/lib/cloud/session.test.ts)、[响应测试](../src/lib/cloud/response.test.ts)、[SDK 适配](../src/lib/cloud/domestic.ts)。

## 4. 为什么拆分演示与云端

`/demo` 使用虚构内容和当前浏览器存储，不需要账号，便于查看界面和交互；`/cloud` 使用真实账号与服务端权限。演示数据不会自动迁移到私人小屋。公开展示不共享个人账号密码。

核查：[演示数据](../src/lib/demo.ts)、[云端入口](../src/components/cloud/cloud-app.tsx)。
